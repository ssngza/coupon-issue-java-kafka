# Product Sense & Business Logic

## 1. 사용자 경험(UX) 보장

- 선착순 이벤트 특성상 유저는 대기 시간 없이 즉시 발급 성공 여부를 응답받아야 함.
- 따라서 DB 트랜잭션이 완료될 때까지 기다리지 않고 Redis 검증 성공 시 즉시 200 OK 응답 반환.
- 즉시 응답은 Redis Lua Script의 재고 차감과 사용자 중복 검증이 성공한 경우에만 반환한다.

## 2. 비즈니스 신뢰성

- 예기치 못한 DB 오류는 Kafka 재시도 후 DLT로 격리한다. DLT 보상은 Redis 재고를 `INCR`하고 발급 사용자 Set을 `SREM`하여 다른 유저가 해당 수량을 다시 발급받을 수 있게 한다.
